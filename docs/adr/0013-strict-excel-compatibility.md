# ADR-0013：采用严格 Excel 功能兼容范围

- 状态：已接受
- 日期：2026-07-23

## 背景

产品要求保持源工作簿格式且不得随意修改受保护内容。不同 Excel 功能在 `.xls`、`.xlsx` 处理组件中的保真程度不同，强行保存可能造成用户不可见的数据损失。

## 决策

- 支持并保留普通单元格值、公式、常规样式、数字格式、合并单元格、行高、列宽、工作表名称及顺序、显示状态、冻结窗格和基础打印设置。
- 加密或需要密码的文件不兼容。
- 启用工作簿结构保护或目标工作表保护的文件不兼容。
- 包含数字签名、外部链接、数据透视表、图表、图片、形状或嵌入对象的文件不兼容。
- 发现当前 Excel 组件无法保证原样保留的其他特殊功能时，同样阻断处理。
- 工具必须报告具体不兼容功能，不得删除或降级该功能后继续生成文件。

## 关于 VBA 宏与外部数据连接的容忍（2026-07-26 修订）

最初的严格范围把 VBA 宏和外部数据连接也列为不兼容。修订后这两类**不再阻断处理**，理由：

- 目标用户的真实交易记录模板（`platform.xlsx` 基线）携带空的 VBA 项目壳与静态数据连接元数据。强制拒绝会让主线样本无法通过，违背产品"服务于用户已有模板"的定位。
- Apache POI 在不修改 VBA 项目结构和连接定义的前提下，重存 `.xlsx` 能保留这两类的容器结构。
- 写入边界本来就只触碰目标工作表最新时间段 A:D 的少量单元格，不与 VBA 代码体或连接刷新逻辑发生交集。

**已知保真风险（写入发布说明）**：POI 重存**不保证**保留宏的代码体或连接的刷新结果，可能在极端情况下丢失非结构性的宏内容。用户若依赖宏运行或连接刷新，应在使用本工具前后自行核对。这是用"容忍"换取"主线可用"的有意取舍。

## 影响

- `platform.xlsx` 样表（含空 VBA 壳与静态数据连接）属于支持范围。
- 产品是严格模板处理工具，不是通用 Excel 编辑器。
- Excel 组件升级或替换时，可以通过专项保真测试逐步扩大支持范围。
